# Code Life CRP Archivist · 3.0 preview

先读取[共同契约](references/common.md)和[当前运行环境](references/runtime.md)。本包是待验证的重写版本，不代表已部署或已迁移 CRP。

**旧库门禁：** 当前权威仍为 CRP 2.0／2.1 时，使用固定 commit 下的 `archive/rp/skills/crp-archivist/SKILL.md` 及其全部适用 references，沿用旧 `crp.py` 流程。本预览不执行正式归档，不因缺少 3.0 对象、数据库或接口报错，不修改旧 schema、审计或水位来满足预览要求。

需要实际变更、迁移或取源时，再读取[操作与验收边界](references/operations.md)。

## 增量归档

1. 固定可用的权威版本，读取当前 schema、能力清单、事务状态、审计水位和动态剧情线注册表。工具或新契约不存在时选择实际可用的兼容流程，不编造接口或执行结果。
2. 比较来源身份和原始字节哈希，接收新增／变更资料。复用历史 source、evidence、entity、work、version 身份，不重分卷、重排或改写历史 raw。新版本追加，原始错误和后来的订正分别保留。
3. 实际审阅本轮资料，区分 RP、OOC、unknown 与混合段落。提出事件、主张、知识取得、关系、研究、承诺、人物档案、事项与文稿候选；模型提取结果不直接成为正式事实。
4. 分别核对发生、取得、版本时间和精度。转录角色不等于剧中说话者；收到、听说、标题接触、实际通读、模仿、照片和亲历分别记录。身份、作者排序、版本或边界不明时保留未知。
5. 文稿沿用唯一正文权威。精确提取有序组成段，不添加标题、过渡、末尾换行或解释；缺全文时不以摘要补正文。同版再次出现只增加接触，新稿建立独立版本。read_by 只从有据的具体版本通读取得生成。
6. 形成带基线、幂等 ID、来源坐标、变更对象、修订关系、审计影响及缺口的变更集。记录审核与发布权限由宿主执行；模型不能通过 confirmed 字段自行授权。
7. 对所有已登记剧情线检查本轮影响。保留既有五线及新增线的动态注册关系，有新证据才推进对应锚点；无变化保持原坐标。相交剧情线、跨现实传播和人物获知必须各有证据。
8. 通过实际可用的唯一事务入口验证与发布。遇并发基线变化重新核对差异，不覆盖他人修改。内容发布与验证水位分开，验证成功才推进 checkpoint。
9. 同输入复跑应无变化，不靠更新时间制造写入。中断保存已完成范围和剩余依赖，失败不宣称归档完成。

微观约定与关系变化追到首次提出及后续兑现／修改／取消，不能只保留最新状态。研究观察、反对意见、假说与已证结论独立；异常记忆共通意象不证明同源。人物状态从当前证据读取，保留配角自主性和用户独占人物边界。

## 召回与验收

普通 RP 取源先绑定现实、分支、人物、故事时点和视图。优先版本只导航，不授予未来或未读版本。精确对白／诗文读取核过的正文；接续包、摘要和缓存不替代原文或角色取得证明。

回归保留现有文稿触发案例、十封信与回信专项、错称到正式题名的导航、五线／新增线接续、原文保真、双向索引和版本／现实／OOC隔离；案例的当前关系状态读取版本化记录，不在技能中写死。

报告分别列出：原文保存、候选、已审核、已发布、已验证、实际阅读范围、剩余缺口。仓库／CLI验证与真实 ChatGPT RP 冷启动分开，未实测标记 UNVERIFIED。归档不自动启动全库审计、日程或付费任务。
