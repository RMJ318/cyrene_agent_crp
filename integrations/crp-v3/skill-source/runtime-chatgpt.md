# ChatGPT 执行适配

先核对当前会话实际可用的仓库连接、文件读取、查询与写入工具。仓库中的 Skill 不代表当前 ChatGPT 已安装相同版本；没有工具时不能声称访问了本机数据库、完整聊天历史、后台任务或源文件。

当前正式入口优先使用固定 commit 的 GitHub 原库，沿用旧 RP 协议与 Skill。查询服务仅在实际工具可用且当前视图已获授权时作为可选入口；认证或工具缺失不阻断旧 GitHub 流程。绑定现实、分支、人物、故事时点和资料版本，缺少必要坐标先澄清或保留未知。不要假设本机 localhost 可以直接访问，也不以静态记忆包替代持续更新的仓库。

当前 ChatGPT 可在会话内拆分查询、读取证据、审阅候选和形成结构化变更。它不等于后台模型提供方或 embedding 接口。没有确定性执行能力时，只报告实际完成的人工／语义部分，将哈希计算、事务及发布标为待执行，不能凭模型生成看似可信的校验值。

只读工具环境只能查源和输出候选变更／审计结果；写入须使用当前任务已授权且实际可用的接口。模型参数里的 confirmed 不等于用户确认。无发布能力保留可接续结果，不能假装提交或提前推进 checkpoint。

整个仓库读取权限下的人物视图是行为协议，不是数据隔离保证。需要服务端强制隔离时使用已授权且实际可用的服务，不能把 GitHub 行为过滤描述成相同保证。精确引用打开具体版本正文，接续摘要不代替来源。

使用实际查询工具、迁移或审计结果时，按[已实现能力与操作边界](operations.md)处理。Actions、普通对话的 MCP/App 和 GitHub 阅读是不同入口；未配置工具就不能声称已调用服务。只读查询不代替 Archivist 发布或 Auditor 语义阅读。
