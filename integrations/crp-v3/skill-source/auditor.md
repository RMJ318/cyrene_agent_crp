# Code Life 全量事实审计 · 3.0 preview

先读取[共同契约](references/common.md)和[当前运行环境](references/runtime.md)。本包未执行全库审计，不以技能重写升级旧结论。

**旧库门禁：** 当前权威仍为 CRP 2.0／2.1 时，使用固定 commit 下的 `archive/rp/skills/crp-fact-auditor/SKILL.md`、其 procedure 和旧 `audit_knowledge.py`。按旧规则续审；3.0 coverage、assessment 等对象未建立不构成旧库错误。不得仅因 Skill 或检索代码版本变化使既有审计失效、批量降级或重签 PASS。

需要记录批次、续审或计算覆盖时，再读取[操作与验收边界](references/operations.md)。

## 固定范围与恢复

固定权威版本、schema、原始源指纹、审计规则及明确的 in-scope 范围；读取有效 finding、coverage、候选和未决依赖。保留指纹仍适用的成果，仅使受新证据或修订影响的项进入复审。旧报告数量不代表当前数量。

区分可用来源、缺失／截断、字面检索范围、实际语义阅读范围和未知剩余量。日序只在同一现实内比较；临近时间、上界、未知日期均按原精度处理。

## 双向审计

- A 线：已登记对象→原文。检查对象、知识取得与后续演变。
- B 线：原文逐消息／场景→登记对象。发现未登记事实、接触、版本、承诺变化和独立配角知识。

每批记录基线、主审边界、补读上下文、稳定 ID、已完成 finding、未完成检查、跨批依赖和候选。补读重叠不重复计覆盖。

逐项保留八类 finding：现实与时间精度；参与者及说话者身份；当时所知／所信及范围；取得渠道；后续确认／否认／修订／遗忘与版本；因果及先后；精确来源坐标与版本；RP/OOC/unknown 和跨现实边界。

沿同一对象、别名、作品、约定和研究追查首次披露及所有可用相关后续。无矛盾记录不证明永久有效；无后续提及不证明遗忘；记忆报告存在不证明报告内容真实。来源不够继续缺证，不制造结论。

## 调度与合并

运行环境支持且任务可独立划分时，可少量并行取证；否则串行。所有执行者固定同一基线，只提交隔离批次结果，不直接修改共享正式实体或 checkpoint。主审复核证据、覆盖边界、身份去重及跨批依赖后统一合并。

区分已领取、已交付和已验收，不用调度状态代替审计状态。中断仅接收实际有证据的完成范围，其余保留可续审检查点。

## 状态与完成条件

机器结论仅 PASS、CONFLICT、INSUFFICIENT_EVIDENCE、NOT_REVIEWED。发生来源子审阅不代替完整 status；全文字节校验不代替版本身份、角色接触或语义审计。未执行的检查不能标为调查后缺证或通过。

登记对象检查结束不等于全历史覆盖完成。只有全部 in-scope 必查项完成、来源范围独立核实、反向语义覆盖和跨批依赖均闭合，才允许该范围 audit_complete=true；不要将局部完成解释为整库完成。

通过唯一事务／审计入口保存结果，验证后推进水位。报告四状态数量、检查完成量、候选／新登记、覆盖与未读范围、依赖、来源缺口、原文保护、实际测试及发布验证结果。无法完成本轮时交付真实检查点，不伪造全量完成。
